## 2. 推荐阅读顺序

### 第一次：跑通链路

1. `MvcConfig` → 两个拦截器。
2. `ShopController` → `ShopServiceImpl` → `CacheClient`。
3. `VoucherOrderController` → `VoucherOrderServiceImpl` → `seckill.lua` → `SeckillVoucherListener`。
4. `AiAgentController` → `AiAgentServiceImpl` → `ChatMessageCreatedEventListener` → `ManualToolAgentLoopExecutor`。

### 第二次：按技术主题

- 缓存：`CacheClient`、`BloomFilterInitializer`、`ShopServiceImpl`。
- 秒杀：`VoucherOrderServiceImpl`、`SeckillVoucherListener`、`OrderTimeoutListener`、Lua 文件。
- 限流：`SlidingWindowLimitAspect`。
- Agent：`ManualToolAgentLoopExecutor`、`AgentLoopPromptProvider`、`AgentLoopToolRegistry`。
- RAG：`AiVectorIndexServiceImpl`、`AiRagRetriever`、`CommonConfiguration`。

## 3. 如何定位 Bug

### 3.1 从日志开始

项目日志以 `com.hmdp` 为主。关键日志有：

- 布隆过滤器预热。
- 秒杀库存预热。
- 限流触发。
- MQ 消费。
- Agent Loop trace。
- SSE 发送失败。

### 3.2 从状态和数据开始

排查秒杀：

1. 查 Redis：
   - `seckill:stock:{voucherId}`
   - `seckill:order:{voucherId}`
   - `seckill:order:pending:{orderId}`
2. 查 MySQL：
   - `tb_voucher_order`
   - `tb_seckill_voucher.stock`
3. 查 RocketMQ：
   - `seckill-order-topic:create`
   - `order-timeout-topic:close`

排查 AI：

1. 查 `tb_ai_conversation` 和 `tb_ai_message`。
2. 查 Milvus collection：
   - `knowledge_vector`
   - `shop_profile_vector`
   - `blog_review_vector`
3. 看 SSE 前端事件类型，判断卡在 `queued`、`status` 还是 `answer_delta`。

### 3.3 断点建议

- `ShopServiceImpl.queryById`：缓存命中/回源。
- `VoucherOrderServiceImpl.seckillVoucher`：Lua 返回码。
- `SeckillVoucherListener.onMessage`：消息消费。
- `ManualToolAgentLoopExecutor.execute`：每一步循环。
- `AiRagRetriever.searchKnowledge`：向量召回和 fallback。

## 4. 常见排查点

### 4.1 秒杀库存为 0 但 Redis 未初始化

Lua 返回 3，`tryWarmupSeckillStock` 按需补热。若仍返回 3，检查：

- `tb_seckill_voucher` 是否有数据。
- `SeckillStockInitializer` 是否启动成功。
- Redis key 是否被误删。

### 4.2 重复下单

Lua 返回 2 表示 `seckill:order:{voucherId}` Set 已有用户。可能是：

- 用户重复请求。
- 上次下单失败但 Set 未回滚。

### 4.3 订单一直 pending

检查：

- RocketMQ 消费者是否在线。
- `seckill-order-topic:create` 是否堆积。
- 消费时是否抛异常。

### 4.4 AI 没有回复

检查：

- 用户消息是否写入 `tb_ai_message`。
- `ChatMessageCreatedEvent` 是否被监听。
- 线程池 `aiAgentTaskExecutor` 是否满。
- `ChatModel` 是否可调用。
- `AgentLoopExecution.status` 是否为 ERROR。

### 4.5 SSE 无输出

检查：

- 前端是否先建立 SSE，再发送 chat。
- `userId + conversationId` 是否一致。
- 后端是否发送了 `connected`。
- 浏览器网络请求是否保持。

## 5. 增加新功能的思路

### 5.1 增加一个普通接口

1. Entity 或 DTO。
2. Mapper。
3. Service 接口 + 实现。
4. Controller。
5. 如有高频读，接入 `CacheClient`。
6. 如需要登录，确认拦截器范围。

### 5.2 增加一个 AI 工具

1. 新建 `@Component`。
2. 写 `@Tool(description = "...")` 方法。
3. 方法参数加 `@ToolParam(description = "...")`。
4. 在 `AgentLoopToolRegistry` 构造器注入该 Bean。
5. 在 System Prompt 或工具描述里让模型知道何时调用。
6. 如涉及外部服务，参考 `LocalLifeMcpService` 做降级。

### 5.3 增加一个向量集合

1. 在 `application.yaml` 增加 collection 名称。
2. 在 `AiAgentProperties.Rag.Collections` 增加字段。
3. 在 `CommonConfiguration` 增加 `@Bean`。
4. 在 `AiVectorIndexServiceImpl` 增加重建逻辑。
5. 在 `AiRagRetriever` 增加检索逻辑，必要时增加 Tool。

## 6. 阅读代码时可关注的“不一致点”

这些不是严重错误，但面试时如果能主动发现，说明你真的读了代码：

1. `ShopServiceImpl` 当前使用 `queryWithPassThrough`，而 README 大篇幅讲逻辑过期。可以说明实现已经准备好，但默认配置未切换。
2. `RateLimit.lua` 文件存在，但 `SlidingWindowLimitAspect` 内联了另一份 Lua，实际没有加载这个文件。
3. `AiAgentProperties.Streaming` 默认 `timeoutSeconds = 45`，但 `application.yaml` 配的是 75；以配置优先。
4. `Mcp.enabled` 默认 false，因此路线/天气工具实际走本地 fallback。
5. `VectorDistanceUtils` 在 main 代码中没有被直接使用，更像测试/备用工具类。
6. 普通券 `buyVoucher` 只创建未支付订单，没有明显库存扣减逻辑；秒杀库存才单独处理。

把这些点说成“阅读发现”，会比单纯背项目更有说服力。
