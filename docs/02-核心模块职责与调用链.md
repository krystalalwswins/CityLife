# 核心模块职责与调用链

## 1. Web 配置与拦截器

入口类：`HmDianPingApplication`

配置类：

- `MvcConfig`：注册两个拦截器。
  - `RefreshTokenInterceptor` order 0：读取 `Authorization` 头，从 Redis Hash 恢复用户到 `UserHolder`，并刷新 token TTL。
  - `LoginInterceptor` order 1：如果 `UserHolder` 无用户，返回 401，否则放行。
- `MvcConfiguration`：CORS 全局配置。
- `JacksonConfig`：Long 序列化为 String，避免前端精度丢失。
- `MybatisConfig`：MyBatis-Plus 分页插件。
- `RedisConfig` / `RedissonConfig`：Redis 与 Redisson 客户端。
- `WebExceptionAdvice`：统一处理 `RateLimitExceededException` 和 `RuntimeException`。

关键点：

- “恢复登录态”和“是否必须登录”被拆成两个拦截器。
- `/shop/**`、`/voucher/**`、`/shop-type/**`、`/blog/hot`、`/user/code`、`/user/login` 等被 `LoginInterceptor` 排除，游客可访问。

## 2. 通用工具层

### UserHolder

用 `ThreadLocal<UserDTO>` 保存当前用户。`RefreshTokenInterceptor` 写入，`afterCompletion` 清理。

### CacheClient

封装 Redis 缓存模板方法：

- `queryWithPassThrough`：缓存穿透处理，命中空值直接返回 null，未命中回源并写空值/真实值。
- `queryWithMutex`：缓存击穿互斥锁方案。
- `queryWithLogicalExpire`：逻辑过期 + 后台线程重建。
- `setWithLogicalExpire`：写入带 `expireTime` 的 `RedisData`。

### RedisIdWorker

基于 Redis `INCR` 生成全局 ID：

```text
timestamp(相对 BEGIN_TIMESTAMP) << 32 | 当天自增序列号
```

### SimpleRedisLock

Redis 分布式锁：

- `setIfAbsent(key, uuid-threadId, leaseTime)`
- 释放时执行 `unlock.lua`，先校验值再删除，保证原子性。

### SlidingWindowLimit / SlidingWindowLimitAspect

注解 + AOP + Redis ZSet + Lua 实现滑动窗口限流。支持全局和用户级两种 key 维度。

### BloomFilterConfig / BloomFilterInitializer

店铺、优惠券两个 Redisson `RBloomFilter`。启动时分页加载 MySQL 主键预热。

### SeckillStockInitializer

启动时把 `tb_seckill_voucher.stock` 同步到 Redis，避免旧数据没有库存 key。

## 3. 普通业务模块

### 用户登录与签到

- `UserController / UserServiceImpl`
- 验证码登录：手机号校验 → 验证码写 Redis → 登录时校验 → 不存在则创建用户 → 写 token Hash。
- 签到：`SETBIT` 写入当月签到位；统计连续签到用 `BITFIELD` 和位运算。

### 店铺

- `ShopController / ShopServiceImpl`
- 详情：布隆过滤器 → `CacheClient.queryWithPassThrough`。
- 更新：先更新 MySQL，再删除 Redis 缓存。
- 分类分页：
  - 无坐标：MyBatis-Plus 分页。
  - 有坐标：Redis GEO `GEOSEARCH` 按 5km 查询，再按 ID 回查 MySQL。

### 探店笔记

- `BlogController / BlogServiceImpl`
- 点赞：MySQL `liked ± 1`，Redis ZSet 记录点赞用户和时间。
- Top5 点赞用户：`ZRANGE` + MySQL `ORDER BY FIELD`。
- 发布笔记：保存 MySQL，向每个粉丝的 `feed:{userId}` ZSet 推送笔记 ID。
- 关注流：用 `ZREVRANGEBYSCORE` 做滚动分页。

### 关注

- `FollowController / FollowServiceImpl`
- MySQL 保存关注关系；Redis Set `follows:{userId}` 同步维护。
- 共同关注：两个 Set 求交集。

## 4. 优惠券、订单、支付模块

### 普通券

`VoucherOrderServiceImpl.buyVoucher`：

1. 校验券存在、上架、非秒杀券。
2. `RedisIdWorker.nextId("order")` 生成订单 ID。
3. 创建未支付订单并落库。

### 秒杀券

见 `03-四类请求链路详解.md` 的秒杀链路。

### 支付

`PaymentController / PaymentServiceImpl`：

- 创建支付前校验：订单存在、属于当前用户、状态为未支付。
- 支付回调用 `SimpleRedisLock` 加锁，状态机：未支付 → 已支付。
- `checkPaymentStatus` 支持订单尚未落库时读取 Redis pending 标记。

## 5. RocketMQ 模块

`RocketMQConstants` 定义：

- `seckill-order-topic:create`
- `order-timeout-topic:close`
- 支付超时时间 15 分钟

消费者：

- `SeckillVoucherListener`：消费秒杀下单消息，异步落库并扣 MySQL 库存。
- `OrderTimeoutListener`：消费延迟消息，加锁后关闭超时订单并回滚库存。

## 6. AI 模块

### Controller

`AiAgentController` 提供：

- 会话：创建、列表、消息列表
- SSE：`/conversations/{id}/stream`
- 聊天：`/chat`、`/messages`
- 推荐：`/recommend`
- 单店分析：`/analyze/shop/{shopId}`
- 索引重建：`/index/rebuild/all`、`/index/rebuild/shop/{shopId}`

### Service

`AiAgentServiceImpl`：

- 会话创建/查询。
- 用户消息落库并发布 `ChatMessageCreatedEvent`。
- 同步推荐/分析直接调用 `AgentLoopExecutor`。

### 事件监听

`ChatMessageCreatedEventListener`：

- `@Async("aiAgentTaskExecutor")` + `@TransactionalEventListener(phase = AFTER_COMMIT)`。
- 每个会话用 `ConversationExecutionCoordinator.runSerial` 串行化，避免同一会话并发乱序。
- 执行 Agent Loop，再流式生成最终答案，写回消息表，推送 SSE。

## 7. AI 数据与基础设施

### Memory

`DbConversationMemoryService`：

- `tb_ai_conversation`：会话。
- `tb_ai_message`：用户、助手、工具消息。
- 上下文只加载最近 `windowSize * 2` 条 user/assistant 消息。
- 工具日志落库，但不进入上下文窗口。

### RAG

- `AiVectorIndexServiceImpl`：构建三类向量索引。
- `AiRagRetriever`：向量检索 + 知识库关键词 fallback。
- `CommonConfiguration`：创建三个 `VectorStore` Bean 和 Milvus Client。

### MCP

`LocalLifeMcpService`：路线/天气外部工具调用，带白名单、超时、本地 fallback。

详细内容见 `05-AI-Agent深度分析.md`。
